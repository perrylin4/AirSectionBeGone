# 2026-11-11 A/B 基准

这组数据用于比较同一个模组构建在 `airsectionbegone.enabled=true/false` 下的差异。关闭组仍会加载 mixin 类，但所有折叠、写时复制和队列逻辑都在首个静态分支返回；因此它是低噪声的“优化逻辑关闭”基线，不等同于彻底移除 JAR。

## 环境

- CPU：Intel Core i5-14490F，16 逻辑处理器
- 内存：63.8 GiB
- 系统：Windows 10 19045
- 服务端运行时：OpenJDK 25.0.4.1；产物仍以 Java 21 为目标
- Minecraft 1.21.11、Fabric Loader 0.20.1、Fabric API 0.141.6、Lithium 0.21.4
- JVM 堆：两组均为 `-Xms2G -Xmx2G`
- 无玩家；同一存档先完成生成、保存和重启，再分别测开/关组
- `forceload add 0 0 255 255` 固定 16×16（256）个区块；启动日志因区块票据边界报告加载 400 个 persistent chunks

## 场景

### 4064 高空世界

- `min_y=-2032`、`height=4064`、每区块 254 个 section；
- 空超平坦生成器，方块全为空，群系为 `minecraft:the_void`；
- 实际验证可在 `y=2000` 和 `y=-2000` 放置并移除方块；
- 预热 2000 个快速刻，随后执行 5 轮 `tick sprint 5000`。

### 标准原版世界

- 原版 normal 噪声地形与默认世界高度；
- 为消除无玩家基准中的生物数量和昼夜/天气噪声，两组共同设置 `spawn_mobs=false`、`mob_drops=false`、`advance_time=false`、`advance_weather=false`，并清空非玩家实体；
- `random_tick_speed` 保持原版默认值；
- 预热 5000 个快速刻，随后执行 7 轮 `tick sprint 10000`。

## 结果

MSPT 由每轮 `tick sprint` 输出的 ticks/s 反算。表中给出中位数与完整范围；这些是无玩家快速刻的 CPU 微基准，不代表有玩家服务器的绝对 MSPT。

| 场景 | 优化关闭 MSPT | 优化开启 MSPT | 中位数变化 |
| --- | ---: | ---: | ---: |
| 4064 高空世界 | 0.2008 ms/t（0.1974–0.2092） | 0.1113 ms/t（0.1082–0.1185） | -44.58% |
| 标准原版世界 | 0.1227 ms/t（0.1199–0.1243） | 0.1180 ms/t（0.1110–0.1187） | -3.81% |

内存主指标来自显式 `jcmd GC.run` 后的 `GC.class_histogram` 总存活对象字节数。它比固定提交 2 GiB G1 堆时的进程 RSS 更能反映本优化实际删除的 Java 对象。

| 场景 | 优化关闭存活堆 | 优化开启存活堆 | 节省 |
| --- | ---: | ---: | ---: |
| 4064 高空世界 | 278,742,896 B（265.830 MiB） | 254,533,088 B（242.742 MiB） | 24,209,808 B（23.088 MiB，8.69%） |
| 标准原版世界 | 241,367,592 B（230.186 MiB） | 239,848,808 B（228.738 MiB） | 1,518,784 B（1.448 MiB，0.63%） |

对象直方图也直接验证了去重规模：

| 场景 | `PalettedContainer` 关闭 | `PalettedContainer` 开启 | 减少 |
| --- | ---: | ---: | ---: |
| 4064 高空世界 | 457,708 | 245,872 | 211,836（46.28%） |
| 标准原版世界 | 42,432 | 28,446 | 13,986（32.96%） |

4064 高世界开启时只存在 4 个本模组不可变容器（3 个空气状态池加 1 个实际使用的虚空群系池）；标准世界为 8 个（3 个空气池加 5 个本次加载区域实际命中的均匀群系池）。`LevelChunkSection` 与 Lithium `SectionData` 数量在开关两组完全相同，符合“保留 section/监听器身份，只共享内部容器”的设计。

## 指定三场景存活堆复测

以下是同日按指定场景追加的内存测试。两组都使用 `-Xmx8G`，主指标仍为 `GC.class_histogram` 在 Full GC 后统计的存活对象总字节数；因此不使用 G1 已提交堆或进程 RSS。关闭组是同一 Fabric/Lithium/模组构建加 `-Dairsectionbegone.enabled=false`，不是卸载整个 JAR。

- 4064 纯虚空与 4064 标准超平坦：同一已保存世界固定 16×16 个 `forceload` 区块，启动日志实际报告 400 个 persistent chunks。
- 标准世界 32 视距：一个真实开发客户端以 32 渲染距离连接，服务器 `view-distance=32`、`simulation-distance=10`；同一世界、同一玩家位置连续采样稳定后重启 A/B。
- 标准世界两组均稳定为 9,802 个 `LevelChunkSection[]`、235,248 个 `LevelChunkSection`，即每个区块数组 24 段；禁用生物生成并冻结时间、天气以降低噪声。

| 场景 | 优化关闭存活堆 | 优化开启存活堆 | 节省 |
| --- | ---: | ---: | ---: |
| 4064 高度纯虚空 | 280,926,720 B（267.913 MiB） | 256,625,768 B（244.737 MiB） | 24,300,952 B（23.175 MiB，8.65%） |
| 标准世界，真实 32 视距 | 593,335,288 B（565.849 MiB） | 578,012,728 B（551.236 MiB） | 15,322,560 B（14.613 MiB，2.58%） |
| 4064 高度标准超平坦 | 282,955,320 B（269.847 MiB） | 259,431,144 B（247.413 MiB） | 23,524,176 B（22.434 MiB，8.31%） |

| 场景 | `PalettedContainer` 关闭 | `PalettedContainer` 开启 | 减少 |
| --- | ---: | ---: | ---: |
| 4064 高度纯虚空 | 457,708 | 245,872 | 211,836 |
| 标准世界，真实 32 视距 | 470,496 | 314,004 | 156,492 |
| 4064 高度标准超平坦 | 449,072 | 246,272 | 202,800 |

标准 32 视距的连续采样总堆有约 0.3 MiB 的正常运行噪声，但区块数组、section 和容器数量完全不变；表中采用两组稳定采样中的较低值。对应节省量约为 14.6 MiB，结论不会受这一级噪声影响。

## 解读限制

- 高空纯空世界是本优化的优势场景，不能把 44.58% 的快速刻变化外推到普通整合包。
- 标准世界的内存收益较小，因为含地形的 section 不能共享方块容器；这里主要回收高空 section 和均匀群系容器。
- RSS 受 G1 已提交堆、JIT、线程栈和操作系统工作集回收影响，本次没有把它作为结论指标。
- 更完整的生产评估仍应加入真实玩家、实体、红石与模组区块负载，并运行数小时以上。
